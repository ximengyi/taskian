# Taskian 0.5 需求与验收

## 状态

需求规划中，尚未开始开发。

## 目标

0.5 将 Taskian 从“微信单通道 + 会话级当前项目”升级为“微信与飞书同时在线 + 个人模式全局当前项目”的本地 Agent 调度器。

用户应当能够在微信或飞书中用自然语言持续安排任务，通过带稳定数字 ID 的项目列表快速切换工作目录；切换后，无论后续消息是否携带 `#task`，都默认在新的全局当前项目中执行。

## 一、微信与飞书多通道

### 1.1 同时在线

- 一个 Taskian 进程可以同时启用腾讯 iLink（微信）和飞书，而不是只能选择一个 `channel.type`。
- 微信 0.4 的扫码登录、消息去重、长轮询和回复行为保持兼容。
- 飞书使用企业自建应用的机器人能力接收和发送消息。
- 飞书默认使用 WebSocket 长连接接收事件，不要求用户部署公网域名、HTTPS 回调服务或路由器端口映射，适合 Windows 个人电脑和纯命令行 Linux 服务器。
- 优先采用飞书官方 Go SDK 的 Channel/WebSocket 能力，复用其消息标准化、断线重连和发送接口：
  - <https://github.com/larksuite/channel-sdk-go>
  - <https://github.com/larksuite/oapi-sdk-go/blob/v3_main/doc/channel.zh.md>
- 通道临时故障应相互隔离；飞书断线不能阻止微信继续收发，微信断线也不能停止飞书。

### 1.2 配置迁移

配置由单个 `channel` 扩展为 `channels`：

```json
{
  "mode": "personal",
  "default_agent": "codex",
  "channels": [
    {
      "type": "ilink",
      "state_path": "~/.taskian/ilink.json"
    },
    {
      "type": "feishu",
      "state_path": "~/.taskian/feishu.json"
    }
  ]
}
```

- 加载旧版配置时自动把 `channel` 视为只有一个元素的 `channels`，不要求用户手动修改。
- 同一类型默认只能配置一个实例；未来多飞书租户不属于 0.5 范围。
- `taskian check` 和启动预检分别显示每个通道的状态。

### 1.3 飞书初始化

新增统一命令：

```text
taskian feishu setup
taskian feishu status
taskian feishu logout
```

`setup` 应提供两种方式：

1. **自动注册优先**：在飞书官方 SDK 和当前租户支持时，使用设备授权流程打印二维码及可复制链接，申请机器人、消息发送权限和 `im.message.receive_v1` 事件订阅。
2. **手动配置兜底**：提示用户在飞书开放平台创建企业自建应用、启用机器人、配置 App ID/App Secret、订阅接收消息事件、发布应用并由管理员审批。

自动注册无法替代企业管理员审核时，必须清楚显示当前所处步骤，不能错误报告“已经可用”。

App Secret、tenant token 等凭据写入 `~/.taskian/feishu.json`，权限限制为当前系统用户可读；也允许使用 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 环境变量。日志、微信回复、飞书回复和 `status` 命令不得输出完整 Secret 或 token。

### 1.4 飞书身份绑定与消息范围

- 个人模式不能把“第一个给机器人发消息的人”自动视为所有者。
- `setup` 在本机终端生成短时有效的一次性绑定码；用户在飞书私聊机器人发送 `绑定 <确认码>` 后，Taskian 保存其 `open_id` 为个人模式所有者。
- 默认接受已绑定所有者的私聊消息。
- 群聊中只有已绑定所有者 `@Taskian` 的消息才创建任务；机器人回复原群聊并关联原消息。
- 其他用户收到明确但不泄露本机信息的拒绝提示；受控模式可配置额外允许用户或群聊。
- 飞书事件使用 `message_id` 做幂等键，重连或平台重试不得重复创建任务。

### 1.5 0.5 支持的飞书消息

- 必须支持文本消息、富文本中的文本内容以及 `@Taskian` 后的任务文字。
- Taskian 的已接收、完成、失败、等待回答、项目列表和帮助消息均能在飞书正确显示。
- 长消息按飞书限制安全分段，保留任务号和顺序。
- 0.5 暂不要求处理用户发送的图片、音频、视频、压缩包和普通附件；收到时返回明确的“不支持此消息类型”提示，不静默忽略。
- 0.5 暂不要求流式刷新消息卡片；继续采用“已接收 + 最终结果/问题”的稳定交互。

## 二、带数字 ID 的项目注册表

### 2.1 稳定自增 ID

每个项目除名称、路径外增加一个本机稳定的正整数 ID：

```text
[1] global       C:\Users\Administrator
[2] taskian      D:\cursorwork\taskian
[3] week-report  D:\cursorwork\week-report
```

- ID 使用 SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` 生成。
- ID 一经分配不因项目改名、路径更新、Taskian 重启或排序变化而改变。
- 删除项目后不复用旧 ID，避免用户凭记忆选择到另一个目录。
- 项目名称继续保持唯一且不区分大小写。
- `#project add` 成功后回复新项目 ID、名称和规范化绝对路径。

### 2.2 数据迁移

- 0.4 的 `projects` 表在首次打开 0.5 时事务化迁移，为已有项目按原创建时间分配 ID。
- 迁移必须保留名称、路径、创建时间、更新时间、最近使用时间和当前项目引用。
- 个人模式没有注册项目时，自动注册当前用户主目录为 `global`，使全新安装始终有一个默认项目。
- 旧配置文件 `projects` 中的项目在启动时导入注册表；同名同路径不重复创建，同名不同路径要求用户处理冲突。
- 迁移失败必须回滚，旧数据库仍可读取或恢复，不能留下半迁移状态。

## 三、全局默认项目与全局切换

### 3.1 个人模式语义

- 个人模式只有一个 `active_project_id`，持久化在 SQLite，称为“当前项目”。
- 当前项目同时适用于微信、飞书、程序重启后的新任务以及所有没有明确指定目录的 Agent。
- 用户在微信切换项目后，飞书后续消息也使用新项目；反向同理。
- 当前项目被删除时，自动回退到配置的默认项目；默认项目也不可用时回退到 `global`，并主动通知用户。
- 项目目录暂时不存在时不自动切换到其他目录，任务创建前返回可理解的错误。

受控/多用户模式不共享一个全局当前项目，而是按授权用户保存当前项目，避免一名用户切换后影响其他人。

### 3.2 寻址优先级

任务目录按以下顺序确定：

1. 本条消息明确指定的项目 ID、项目名称或绝对目录；
2. 个人模式的全局 `active_project_id`；
3. 配置的 `default_project`；
4. 自动注册的 `global` 项目。

切换当前项目后，以下消息全部在当前项目执行：

```text
帮我运行一下测试
#task 帮我运行一下测试
#codex 帮我检查登录模块
#cursor 修复移动端布局
```

`#task`、`#codex`、`#cursor` 只负责选择任务类型或 Agent；没有显式项目参数时，不再把第一段普通任务文字误判成项目名称。

### 3.3 查询当前项目

以下表达均查询当前项目，不启动 Agent、不消耗模型 token：

```text
当前项目
查询当前项目
项目状态
#project current
project current
```

回复示例：

```text
当前项目
[2] taskian
目录：D:\cursorwork\taskian
默认 Agent：codex
来源：全局选择
```

## 四、友好的项目列表与数字切换

### 4.1 项目列表

以下表达均打印项目列表，不启动 Agent：

```text
项目列表
所有项目
列出项目
projects
#project list
```

回复按 ID 升序，带总数和当前标识：

```text
项目列表（3 个）
[1] global       C:\Users\Administrator
[2] taskian  ★   D:\cursorwork\taskian
[3] week-report  D:\cursorwork\week-report

回复项目 ID 可切换，例如：3
```

列表较长时安全分段，每段重复说明当前项目；不得因微信或飞书消息长度限制截掉路径。

### 4.2 选择项目

始终支持明确语法：

```text
切换项目 3
使用项目 3
项目 3
#use 3
#use taskian
```

友好数字选择规则：

- 用户刚收到“项目列表”后的 5 分钟内，且当前没有 Agent 等待其回答时，可以只回复 `3` 切换项目。
- 不在项目选择上下文时，孤立数字不能自行切换项目，避免把普通回答误当控制命令。
- 有 Agent 正在等待回答时，孤立数字优先作为 Agent 回答；切换项目必须发送 `切换项目 3` 或 `#use 3`。
- ID 不存在、项目已删除或路径不可访问时返回明确错误，当前项目保持不变。
- 切换成功后同时显示 ID、名称和路径，并明确提示“微信和飞书后续任务均使用此项目”。

### 4.3 项目管理补充

保留 0.4 命令并同时接受 ID 或名称：

```text
#project show 3
#project rename 3 taskian-core
#project path 3 D:\new-workspace\taskian
#project remove 3
#project add taskian D:\cursorwork\taskian
```

- `path`：修改项目实际目录，不改变项目 ID 和名称；同时支持自然语言形式 `修改项目路径 3 D:\new-workspace\taskian`。
- 新路径必须是当前操作系统上的绝对目录；Taskian 应规范化路径并检查目录确实存在，验证失败时保留原路径。
- Windows 路径允许包含空格，解析时项目 ID/名称之后的全部内容均视为路径，不要求用户手工添加引号；带引号的路径也应正确去除外层引号。
- 修改当前项目的路径后，微信和飞书中的后续任务立即使用新路径，不需要再次切换项目。
- 修改路径只影响新任务；已创建、运行中和历史任务继续使用创建时保存的目录快照。
- 新路径已经被另一个项目登记时，Taskian 返回冲突项目的 ID 和名称，不静默创建两个指向相同目录的项目。
- `remove` 继续只删除注册信息，不删除磁盘目录。
- 当前项目不能被无提示删除；删除前要求一次明确确认，或先切换到其他项目。
- 项目列表和查询命令是确定性本地操作，不调用 Codex/Cursor，不消耗模型 token。

## 五、命令解析优先级

为避免自然语言任务、项目选择和双向回答相互误路由，消息按以下顺序处理：

1. 安全确认：`#confirm`、飞书绑定确认。
2. 明确控制命令：帮助、项目查询/列表/切换/管理、状态、取消。
3. 明确回答：`#reply <任务号> <回答>`。
4. 唯一等待回答任务的普通回复。
5. 项目列表产生的短时数字选择上下文。
6. 新 Agent 任务：普通文本、`#task`、`#codex`、`#cursor`。

当存在多个等待回答任务时，继续要求完整任务号。控制命令永远不作为 Agent 回答或新任务。

## 六、数据模型与内部架构

### 6.1 SQLite

0.5 至少需要以下变化：

- `projects.id`：稳定自增主键；`name` 改为唯一键。
- `projects.path`：允许通过项目 ID 或名称更新，并对规范化后的路径建立唯一约束；路径变更更新 `updated_at`，不改变 ID、名称和 `created_at`。
- `global_preferences.active_project_id`：个人模式的全局当前项目。
- `sender_preferences.active_project_id`：受控模式的用户当前项目。
- `selection_contexts`：通道、发送者、待选择类型、过期时间，用于项目列表后的数字回复。
- `channel_bindings`：通道类型、平台用户 ID、授权角色和绑定时间。
- `tasks.project_id`：保存项目 ID，同时继续快照 `project` 名称和 `project_path`，保证历史任务不因改名或删除而改变。

### 6.2 通道抽象

现有单个 `Transport` 调整为多通道管理器：

```text
微信长轮询 ─┐
            ├─ MultiTransport ─ Dispatcher ─ Agent
飞书长连接 ─┘
```

- 每个入站消息必须携带稳定的 `Channel`、`Sender`、`Conversation` 和平台消息 ID。
- 出站消息按任务创建时保存的通道返回，不因当前项目或另一通道的新消息改变目的地。
- 飞书 WebSocket 事件通过内部有界队列接入 Dispatcher；队列满时记录错误并采用背压，不能无限创建 goroutine。
- 多通道启动、停止、重连、健康状态和错误日志分别标识通道名称。

## 七、Help 与可发现性

微信和飞书发送 `help`、`#help` 或 `帮助` 时，首页应优先显示最常用的自然语言操作：

```text
当前项目          查看当前项目
项目列表          列出所有项目并按数字选择
切换项目 3        全局切换到项目 3
修改项目路径 3 D:\work\demo
帮我运行测试      在当前项目使用默认 Agent
#codex 检查代码    在当前项目指定 Codex
```

`help project` 显示项目 ID、查询、列表、切换和管理命令；`help channel` 显示微信/飞书状态和本机诊断命令。

## 八、兼容性

- 0.4 的微信命令、项目名称、绝对路径、`#reply`、`#status` 和 `#cancel` 保持可用。
- `#use <名称>` 保持兼容，并新增 `#use <ID>`。
- 旧版会话级当前项目迁移时，以最近使用的有效项目作为个人模式全局当前项目；没有有效值时使用 `default_project` 或 `global`。
- 历史任务继续显示创建时的项目名称和目录快照。
- 飞书支持是可选能力；未配置飞书时不得影响微信启动或增加报错噪音。

## 九、安全边界

- 飞书机器人只能调度运行 Taskian 的本机 Agent，不把 App Secret、iLink 凭据或 Agent 登录数据上传给 Taskian 自有云服务。
- 个人模式必须完成飞书用户绑定，不能仅依赖机器人应用可见范围。
- 群聊默认要求绑定用户 `@Taskian`，避免普通聊天误创建任务。
- 项目 ID 只是本地目录别名，不扩大操作系统权限或 Agent 沙箱权限。
- 项目切换、列表和查询不调用模型；任务正文不经过 shell 解释。
- 关机、重启及未来的高风险本机操作继续要求短时一次性确认码。

## 十、验收标准

- 同一 Taskian 进程可同时从微信和飞书接收文本任务，并把结果返回原通道。
- 飞书采用长连接时无需公网回调地址；断线后自动恢复且同一 `message_id` 不重复执行。
- 未绑定飞书用户不能调度本机 Agent；绑定码过期或错误时不建立关系。
- 微信故障不影响飞书，飞书故障不影响微信；状态和日志能分别定位。
- 0.4 单通道配置无需手工修改即可升级启动。
- 每个项目拥有稳定自增 ID；改名、重启和排序后 ID 不变，删除后 ID 不复用。
- 可以按项目 ID 或名称修改路径；成功后新任务使用新路径，历史及运行中任务的路径快照不变。
- 修改为不存在的目录、相对路径或其他项目已使用的目录时拒绝更新，原路径保持不变。
- 全新个人模式至少存在 `global` 项目和有效全局当前项目。
- “当前项目”在微信和飞书返回相同 ID、名称和路径。
- 在微信切换到项目 3 后，飞书发送普通文本、`#task`、`#codex` 和 `#cursor` 均使用项目 3；反向切换同样生效。
- “项目列表”显示 ID、名称、路径和当前标记；无等待回答任务时可在 5 分钟内只回复数字切换。
- Agent 等待回答时，数字回复不会误切换项目；明确的“切换项目 3”仍能执行控制操作。
- 项目不存在、目录失效和删除当前项目等异常不会悄悄落到错误目录。
- 项目查询、列表和切换不启动 Agent、不消耗模型 token。
- 飞书长消息、重复事件、断线重连、权限不足、应用未发布和 Secret 无效均有自动化测试或可隔离集成测试。
- Windows amd64、Linux amd64、macOS amd64/arm64 构建通过；`go test ./...`、`go vet ./...` 和关键并发竞态测试通过。

## 十一、暂不包含

- 飞书附件、图片、音频和视频作为 Agent 输入。
- 飞书消息卡片的流式增量更新和复杂按钮表单。
- 一个 Taskian 实例连接多个飞书租户。
- 在不同电脑之间同步项目注册表或全局当前项目。
- 用自然语言模糊猜测项目；无法唯一确定时必须列出候选项让用户选择。

## Release Note 摘要（规划）

Taskian 0.5 计划新增飞书机器人通道，并支持微信与飞书同时在线；个人模式新增跨通道共享的全局当前项目、稳定自增项目 ID、当前项目查询、带编号项目列表、项目路径修改和短时数字选择。切换项目后，普通文本及 `#task`、`#codex`、`#cursor` 都默认在该项目执行。飞书采用适合本地电脑和命令行服务器的 WebSocket 长连接，不要求公网回调地址，并通过一次性绑定码保护本机 Agent 入口。
