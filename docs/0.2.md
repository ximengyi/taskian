# Taskian 0.2 需求文档

- 状态：规划中
- 目标版本：0.2
- 主要平台：Rocky Linux amd64、Windows amd64、macOS amd64/arm64
- 需求主题：腾讯 iLink 直连与 Agent 双向会话

本版本的产品设计应遵守 [`product-advantages.md`](product-advantages.md) 中的定位：
Taskian 使用确定性逻辑完成连接与调度，不在用户和编程 Agent 之间增加第二个大模型。

## Release Note 摘要

> 本节在 0.2 发布前根据实际交付结果更新，不能把尚未完成的计划写成已发布功能。

计划在 0.2 中让 Taskian 脱离 Obsidian 桌面环境，直接连接腾讯 iLink，并为 Codex 和 Cursor 提供可恢复的双向会话。当 Agent 在执行中需要用户补充信息或确认操作时，Taskian 会把问题发到微信；用户回复后，Taskian 恢复原 Agent 会话继续执行。

## 1. 背景

Taskian 0.1 的链路是：

```text
微信 → Wechatian → Obsidian 文件 → Taskian → 命令行 Agent
                                      ↓
微信 ← Wechatian ← Obsidian 文件 ← 执行结果
```

该方式适合有 Obsidian 桌面环境的电脑，但在纯命令行 Rocky Linux 服务器上无法完整运行。同时，0.1 每个任务只启动一次 Agent；如果 Codex 或 Cursor 中途需要用户回答问题，Taskian 没有保存 Agent 会话，也没有把回答送回原会话的机制。

0.2 将 Taskian 从“单次任务转发器”升级为“可持久化的双向 Agent 会话调度器”。

## 2. 版本目标

0.2 必须实现：

1. **双向交互**：Agent 可以暂停并向用户提问，微信回复可以恢复同一个 Agent 会话。
2. **Codex 原生适配**：保存 Codex `thread_id`，通过 CLI 的 resume 能力继续原会话。
3. **Cursor 原生适配**：保存 Cursor `session_id`，通过 CLI 的 resume 能力继续原会话。
4. **腾讯 iLink 直连**：Taskian 自己完成扫码登录、收消息、发消息和连接状态维护，不依赖 Obsidian GUI。
5. **服务端运行**：在纯命令行 Rocky Linux amd64 上可安装、登录、作为长期服务运行。
6. **可靠恢复**：Taskian 重启后，等待用户回答的任务仍可继续，消息不会因重复投递而重复执行。
7. **兼容 0.1**：保留 Wechatian 文件通道，用户可以选择 `ilink` 或 `wechatian-files`。

## 3. 非目标

以下能力不作为 0.2 发布的必要条件：

- 在 Taskian 内实现通用聊天机器人或知识库问答。
- 支持任意微信群、群成员权限和复杂群聊路由。
- 同一份配置同时登录多个微信/iLink 身份。
- 通过微信自动批准提权、关闭沙箱、推送代码或生产部署。
- 完整支持微信语音、视频、图片和文件作为 Agent 输入。
- 提供 Web 管理后台或云端控制平面。
- 替代 Codex、Cursor 自身的账号登录、计费和权限系统。

## 4. 总体架构

Taskian 0.2 分为四层：

```text
             ┌─────────────────────────────┐
微信/iLink ⇄ │ iLink 通道                  │
Obsidian   ⇄ │ Wechatian 文件通道（兼容）  │
             └──────────────┬──────────────┘
                            │ 标准消息
             ┌──────────────▼──────────────┐
             │ 调度器、权限检查、会话状态机 │
             └──────────────┬──────────────┘
                            │ 标准 Agent 请求/事件
             ┌──────────────▼──────────────┐
             │ Codex 适配器 │ Cursor 适配器 │
             └──────────────┬──────────────┘
                            │
             ┌──────────────▼──────────────┐
             │ SQLite 状态库与审计日志      │
             └─────────────────────────────┘
```

通道只负责收发消息，不理解 Agent 的具体命令；Agent 适配器只负责启动、恢复和取消会话，不理解微信协议。调度器负责把两者连接起来。

## 5. 用户交互协议

### 5.1 创建任务

保留 0.1 命令格式：

```text
#codex yuanze
检查登录页并运行测试。如果需要决定交互方案，先问我。
```

```text
#taskian cursor yuanze
修复移动端布局。如果有多个可行方案，先问我。
```

Taskian 接收后返回短任务号，例如：

```text
[T-1042] 已接收，Agent：codex，项目：yuanze
```

### 5.2 Agent 提问

当 Agent 需要用户输入时，Taskian 发送：

```text
[T-1042] Codex 等待你的回答：
登录方式要保留密码登录，还是只保留短信验证码？

回复：#reply T-1042 <你的回答>
```

用户回复：

```text
#reply T-1042 两种都保留，短信验证码作为默认方式。
```

Taskian 必须恢复 T-1042 对应的原 Codex/Cursor 会话，而不是创建新任务。

当且仅当当前用户只有一个 `waiting_user` 任务时，可以接受不带任务号的普通回复；存在多个等待任务时必须要求用户指定任务号，防止回答被送错会话。

### 5.3 管理命令

0.2 支持以下命令：

- `#status`：查看当前运行中和等待回答的任务。
- `#status T-1042`：查看指定任务状态。
- `#reply T-1042 <内容>`：回答 Agent 的普通问题。
- `#cancel T-1042`：取消任务，并尽力终止对应的本地 Agent 进程。
- `#help`：显示可用命令和示例。

高风险操作的批准不能混用 `#reply`。若 Agent 请求超出既定权限，Taskian 应拒绝并解释原因；0.2 不通过微信动态扩大沙箱或系统权限。

## 6. 会话状态机

任务状态至少包括：

```text
received → queued → running ───────────────→ completed
                        │                         ↑
                        ├→ waiting_user → resuming┘
                        ├→ failed
                        └→ cancelled
```

状态定义：

- `received`：消息已通过格式和身份检查。
- `queued`：等待可用执行槽。
- `running`：Agent 正在执行。
- `waiting_user`：Agent 会话已保存，正在等待微信回复。
- `resuming`：用户回答已送给原 Agent 会话。
- `completed`：任务成功结束。
- `failed`：任务不可恢复地失败，错误已告知用户。
- `cancelled`：用户取消或管理员终止。

所有状态切换必须持久化。程序崩溃或重启后：

- `waiting_user` 任务继续等待，不得丢失会话 ID；
- 原先处于 `running`/`resuming` 的任务进入恢复检查，不得直接重复执行原始指令；
- 已处理的 iLink 消息不得再次创建任务或重复回答。

## 7. 持久化模型

0.2 使用 SQLite 作为默认状态库，以支持事务、去重和并发会话。每个任务至少保存：

- Taskian 任务号；
- 来源通道、发送者标识和会话标识；
- 入站消息唯一 ID；
- Agent 类型、Agent 会话 ID 和本地进程信息；
- 项目名称和解析后的项目路径；
- 当前状态、原始指令、待回答问题和最近一次用户回答；
- 创建、开始、等待、恢复、完成时间；
- 重试次数、最终摘要和脱敏后的错误信息。

消息唯一 ID 和会话恢复操作必须有幂等约束。数据库默认保存在 Taskian 状态目录中，不得放进 Obsidian 同步目录。

## 8. 统一 Agent 适配器

内部适配器应提供等价能力：

- `Start`：创建 Agent 会话并开始任务；
- `Resume`：向已有会话发送用户回答；
- `Cancel`：终止当前执行；
- `Events`：输出进度、提问、完成和错误事件；
- `HealthCheck`：检查 CLI 是否安装、已登录且版本受支持。

调度器不能通过搜索“请回答”“需要确认”等自然语言猜测 Agent 是否在等待输入。Agent 的最终输出必须转换为统一结果信封：

```json
{
  "status": "needs_input",
  "message": "我需要确认登录方案。",
  "question": "保留密码登录还是只保留短信验证码？"
}
```

或：

```json
{
  "status": "completed",
  "message": "修改和测试已经完成。"
}
```

适配器负责用结构化输出能力、明确的系统提示和严格解析得到该信封。解析失败应作为可诊断错误处理，不能把不确定文本自动当成授权。

### 8.1 Codex 适配器

- 使用非交互模式启动任务并读取 JSONL 事件。
- 从 `thread.started` 事件保存 `thread_id`。
- 优先使用输出 schema 约束最终结果信封。
- 用户回答到达后，通过 `codex exec resume <thread_id>` 恢复同一会话。
- 支持配置 Codex 沙箱、模型和超时时间，但默认保持工作区写入沙箱。
- 解析并转发简短进度，不把完整内部日志持续刷到微信。

参考：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode.md)。

### 8.2 Cursor 适配器

- 使用 Cursor Agent CLI 的 headless/print 模式启动任务。
- 使用 JSON 或 stream-json 输出并保存 `session_id`。
- 用户回答到达后，通过 `--resume <session_id>` 恢复同一会话。
- 是否允许修改文件必须由项目配置决定；不能为方便执行而全局开启无确认高权限模式。
- 固定并检查最低兼容 CLI 版本，输出格式变化时给出明确升级提示。

参考：[Cursor Headless CLI](https://cursor.com/docs/cli/headless)、[Cursor CLI 参数](https://cursor.com/docs/cli/reference/parameters)、[Cursor 输出格式](https://cursor.com/docs/cli/reference/output-format)。

## 9. 腾讯 iLink 直连通道

### 9.1 命令行登录

纯命令行服务器必须可以执行：

```text
taskian ilink login
taskian ilink status
taskian ilink logout
```

`login` 在终端显示可扫码的二维码，并在不支持终端二维码时给出可保存的二维码图片路径。程序轮询登录状态，成功后保存会话并显示已绑定身份。登录失效时，Taskian 发出明确日志并要求重新扫码，不得无限静默重试。

### 9.2 消息收发

iLink 通道必须：

- 长轮询接收新消息并持久化 cursor；
- 保存并在回复时携带正确的上下文 token；
- 按消息 ID 去重；
- 支持发送 Taskian 的文本回执、Agent 问题、状态和最终结果；
- 网络中断时指数退避并自动恢复；
- 遵守 iLink 主动消息额度和频率限制，合并非必要进度；
- 只接受配置中允许的发送者/会话；
- 单个消息过长时安全分段，并保持任务号可见。

0.2 的 iLink 输入最低范围是文本消息。图片、文件和语音可以被识别为“不支持的输入”并给出提示，不要求传给 Agent。

### 9.3 实现来源与兼容性

可参考或移植 Wechatian 已拆分的 Node/Obsidian transport 与 iLink 核心实现，但 Taskian 的 Go 实现不能依赖 Obsidian 运行时。若复制或改写 MIT 代码，应保留上游版权声明和许可证归属，并在仓库中增加第三方声明。

iLink 接口稳定性、使用规则和服务限制是 0.2 的主要外部风险。实现应集中在独立通道包中，避免协议变化影响调度器和 Agent 适配器。

参考：[Wechatian](https://github.com/laruence/wechatian)。

## 10. 配置草案

配置格式以实现阶段最终定义为准，预期结构如下：

```json
{
  "data_dir": "/home/taskian/.local/share/taskian",
  "channel": {
    "type": "ilink",
    "allowed_senders": ["bound-owner"]
  },
  "scheduler": {
    "max_concurrent_tasks": 2,
    "waiting_user_timeout": "72h"
  },
  "agents": {
    "codex": {
      "type": "codex",
      "command": "codex",
      "sandbox": "workspace-write"
    },
    "cursor": {
      "type": "cursor",
      "command": "agent"
    }
  },
  "projects": {
    "yuanze": {
      "path": "/srv/code/yuanze",
      "allowed_agents": ["codex", "cursor"]
    }
  }
}
```

敏感 token 不应直接写进可提交的配置文件。状态目录在 Linux 上应限制为当前用户可访问，token 文件权限应为 `0600`；日志必须对 token、cookie、二维码凭据和用户隐私内容脱敏。

## 11. 兼容与迁移

- 0.1 的 `wechatian-files` 工作方式继续可用，但不再是默认推荐方案。
- 0.1 配置可通过迁移命令或清晰错误提示升级，不允许静默错误解释旧字段。
- 原有 `#codex <项目>` 和 `#taskian <agent> <项目>` 命令保持兼容。
- 0.1 去重状态可导入 SQLite；无法导入时，首次启动仍需默认跳过历史消息。
- iLink 与文件通道不得同时消费同一条微信任务，避免双重执行。

## 12. 安全要求

- 默认只信任扫码绑定的单一所有者，并支持显式发送者白名单。
- 项目必须来自本地白名单，微信消息不能提供任意工作目录或可执行命令。
- 启动 Agent 时不经过 shell，正文只能作为数据参数或标准输入传递。
- Agent 保持最小权限；Taskian 不因微信回复自动提升权限。
- 对提交、推送、发布、部署、删除大量文件和读取项目外文件等行为保持现有沙箱边界。
- 外部文本、仓库内容和网页中的提示不能改变 Taskian 的发送者权限或项目白名单。
- `#cancel` 只能取消当前发送者有权访问的任务。
- 错误消息不得把环境变量、访问令牌或完整敏感命令行发回微信。

## 13. 可靠性与可观测性

- 提供 `taskian check`，检查 iLink 登录状态、数据库、Agent CLI、项目路径和权限。
- 提供 `taskian status`，显示通道连接、队列、运行中与等待回答的任务数量。
- 日志使用结构化字段记录任务号、状态变化、Agent 类型和耗时，不记录密钥。
- Agent 子进程异常退出、超时或 Taskian 重启后，任务状态必须可解释。
- 等待用户超过配置时限后标为失败/过期并通知用户，不能永久占用执行槽。
- 取消、重试和恢复必须幂等；重复微信消息不得造成重复副作用。

## 14. 验收标准

0.2 发布前必须通过以下场景：

1. 在无图形界面、未安装 Obsidian 的 Rocky Linux amd64 上完成 iLink 扫码登录。
2. 微信发送 Codex 任务，Taskian 创建任务并返回任务号。
3. Codex 提出问题后，任务进入 `waiting_user`，问题被发回微信。
4. 用户用 `#reply` 回答，Taskian 使用保存的 `thread_id` 恢复原 Codex 会话并返回最终结果。
5. Cursor 完成同样的提问、回复、恢复流程，并验证使用同一 `session_id`。
6. Taskian 在等待回答时重启，启动后仍能收到回答并恢复正确会话。
7. 两个任务同时等待回答时，不带任务号的回复不会被错误路由。
8. iLink 重复投递同一消息时，只创建或恢复一次任务。
9. 网络中断后自动恢复收消息，不重复执行断线前任务。
10. iLink 登录失效时给出可操作提示，重新登录后恢复服务。
11. 未授权发送者、未知项目、未知 Agent 和越权路径均被拒绝。
12. 日志、状态库导出和微信错误消息中不出现明文 token。
13. Windows amd64、Linux amd64、macOS amd64/arm64 均能构建。
14. 0.1 的 Wechatian 文件通道回归测试通过。

## 15. 测试要求

- 状态机和路由规则单元测试，覆盖非法状态转换和多任务回答路由。
- Codex/Cursor JSON 事件固定样本测试，避免依赖真实账号运行全部自动测试。
- iLink 假服务测试：登录状态、长轮询、cursor、上下文 token、重复消息、限流和断线重连。
- SQLite 崩溃恢复、事务与幂等测试。
- Agent 进程超时、取消和异常退出测试。
- Rocky Linux amd64 手工端到端测试，分别使用 Codex 与 Cursor 完成一次真实双向会话。
- CI 保持 `go test`、静态检查和四平台构建。

## 16. 开发里程碑

### M1：核心会话层

- SQLite 状态库与迁移。
- 状态机、任务号、并发队列和回答路由。
- 通道与 Agent 统一接口。

### M2：Codex 双向适配

- JSONL 事件解析、`thread_id` 持久化。
- 结构化提问/完成结果。
- resume、取消、超时与重启恢复。

### M3：Cursor 双向适配

- stream-json 解析、`session_id` 持久化。
- resume、取消、超时与兼容版本检查。

### M4：iLink 直连

- 终端二维码登录与会话存储。
- 文本消息长轮询、去重、回复与重连。
- 发送者绑定、限流和登录失效处理。

### M5：加固与发布

- Rocky Linux/Windows/macOS 回归。
- 安全审查、第三方许可证声明和运维文档。
- 更新本文件的 Release Note 摘要并发布 0.2。

## 17. 风险与待确认项

- **iLink 稳定性**：接口、登录流程或服务限制可能变化，需要隔离实现并准备兼容策略。
- **服务条款**：发布前需要确认直接接入方式符合腾讯 iLink 的适用规则。
- **Agent 输出稳定性**：Codex/Cursor CLI 版本升级可能改变事件格式，适配器需要最低版本检查和样本测试。
- **等待输入识别**：必须依靠结构化协议，不能只依赖模型自然语言；需要验证两个 CLI 对输出约束的遵循程度。
- **进程恢复边界**：Taskian 崩溃时，本地 Agent 进程可能仍在运行；需要设计进程租约，避免恢复时并发操作同一工作区。
- **同账号多端消费**：需要验证 iLink cursor 在多个客户端同时运行时的行为；0.2 默认只允许一个 Taskian iLink 实例。

## 18. 完成定义

只有当第 14 节的必要场景全部通过、Rocky Linux 纯命令行端到端双向会话可用、文档与安全说明完成，并且 Release Note 摘要已按实际交付更新后，0.2 才能打 Tag 发布。
