# Taskian 版本需求文档

`docs` 目录是 Taskian 每个版本的需求与验收依据。文件按 Git Tag 的版本号命名：

```text
docs/0.2.md
docs/0.3.md
docs/0.4.md
docs/1.0.md
```

跨版本的产品定位、核心优势和对外表述统一维护在
[`product-advantages.md`](product-advantages.md) 中。

## 约定

- 一个版本对应一个 `docs/<版本号>.md` 文件，版本号不带 `v` 前缀。
- Git Tag 使用相同版本号，例如需求文档 `docs/0.2.md` 对应 Tag `0.2`。
- 文档在开发前记录目标、范围、交互协议、验收标准和风险。
- 开发过程中直接更新对应版本文档，并标明被调整或延期的需求。
- 发布前更新文档中的“Release Note 摘要”，Release Note 以该章节和实际提交记录为依据生成。
- 已发布版本的需求文档只修正事实错误，不再悄悄改变需求范围。

## Release Note 生成规则

发布时读取对应版本文档，重点总结：

1. “Release Note 摘要”中的用户可感知变化；
2. “验收标准”中已经通过的能力；
3. 实际延期、移除的需求及已知限制；
4. 升级步骤、兼容性变化和安全注意事项。

需求文档描述“计划实现什么”，Release Note 只描述“最终实际交付了什么”。两者不一致时，以代码、测试结果和最终验收记录为准。
