# Taskian 0.3 需求与验收

## 状态

已实现，等待发布验收。

## 目标

让 Taskian 长期运行时不再依赖用户手动执行 `taskian check`，并能自动找到本机已安装的 Codex/Cursor CLI、持续观察 Agent 和项目目录的可用状态。

## 功能范围

- `taskian serve` 启动后立即预检所有配置的 Agent 和项目目录。
- 单个 Agent 不可用不会阻止调度器启动，其他 Agent 仍可接收任务。
- 默认每 5 分钟检查一次；只在首次发现故障或状态发生变化时提醒，避免重复刷屏。
- Codex 检查 CLI 与 `codex login status`，Cursor 检查 CLI 与 `agent status`；检查不发起模型请求，不消耗模型 token。
- iLink 默认向扫码绑定用户/发送者白名单提醒；可用 `health.notify_senders` 明确指定接收者。
- 新增 `taskian agents detect` 与 JSON 输出，检查 PATH 和跨平台常见安装目录，不进行全盘递归扫描。
- 配置的命令找不到时，`serve` 自动采用探测到的同类型 CLI 路径。
- 保持 0.2 配置兼容；未提供 `health` 时默认启用，间隔为 `5m`。

## 配置

```json
"health": {
  "enabled": true,
  "interval": "5m",
  "notify_senders": []
}
```

将 `enabled` 设为 `false` 可关闭后台定时检查；启动预检仍会执行并写日志。`notify_senders` 通常无需配置，iLink 会使用绑定用户。

## 验收标准

- Windows、Linux amd64、macOS amd64/arm64 均可编译。
- `agents detect` 能输出已发现的 Agent 类型、绝对路径和来源。
- 启动时能报告 Agent 登录状态和项目路径状态。
- 相同故障连续出现时不重复提醒；故障和恢复各提醒一次。
- 健康检查不调用模型推理。
- 0.2 示例配置升级后可直接加载。

## 已知限制

- 探测只覆盖 PATH 和常见安装位置，自定义位置仍需配置绝对路径。
- Agent 自带的 `status` 命令只能证明其登录状态检查通过；真实任务仍可能受网络、额度或服务端故障影响。
- 文件通道无法自动推断健康提醒接收者，需要配置 `health.notify_senders`，或只查看日志。

## Release Note 摘要

0.3 增加自动 Agent 探测、启动预检和定时健康检查。Taskian 可以在 PATH 或常见目录中找到 Codex/Cursor，在登录状态、CLI 或项目目录发生故障与恢复时通过 iLink 提醒用户。旧配置无需修改即可启用默认 5 分钟健康检查。
