# Taskian 0.4 需求与验收

## 状态

实现完成，发布验收中。

## 目标

将 Taskian 从“预先配置项目白名单的调度器”升级为适合个人使用的全局 Agent 入口：首次运行即可完成配置和微信绑定，任务既可直接指定目录，也可使用持久化的项目名称；用户忘记语法时能够直接在微信中发送 `help` 获取帮助。

## 一、个人模式与全局配置

- 默认采用个人模式，不要求预先配置项目列表，也不限制只能使用某几个已登记项目。
- 自动探测本机 Codex 和 Cursor；两者存在时默认均可使用。
- 配置 `default_agent`，任务未指定 Agent 时使用默认值，默认优先选择 Codex；Codex 不存在时选择已探测到的其他 Agent。
- 允许任务直接指定 Windows、Linux 或 macOS 的绝对目录。
- 项目目录的最终访问权限仍由运行 Taskian 的系统用户和 Agent 自身沙箱决定，Taskian 不绕过操作系统权限。
- 保留可选的受控模式，供需要 Agent、项目根目录或发送者白名单的用户使用；0.3 的严格配置可继续加载。
- 个人模式不要求填写 `allowed_senders`。iLink 仍只接受扫码绑定身份，扫码身份是默认授权边界。

## 二、项目名称与目录注册

项目名称是持久化的目录别名，而不是个人模式下的访问白名单。注册信息保存在 SQLite 中，Taskian 重启后仍然有效。

### 项目管理命令

```text
#project add week-report D:\cursorwork\week-report
#project list
#project show week-report
#project rename week-report weekly-report
#project remove week-report
#project find week-report D:\
#use week-report
```

- `add`：验证并规范化目录后保存名称与路径；项目名称不区分大小写。
- `list`：列出项目名称、实际目录及当前项目标识。
- `show`：显示一个项目的目录和最近使用信息。
- `rename`：修改项目名称，不移动磁盘目录。
- `remove`：删除别名，不删除目录或任何项目文件。
- `find`：由 Taskian 按目录名查找候选项，不调用模型、不消耗 token；必须指定搜索根目录，禁止默认全盘无界扫描。
- `use`：将项目设置为当前微信会话的默认项目，并持久化到 SQLite。

名称冲突、目录不存在或找到多个候选项时，Taskian 不自行猜测，通过微信返回明确的选择或修正命令。

用户也可以先让 Agent 查找目录，再用明确路径注册：

```text
#project add week-report D:\Agent找到的目录
```

Taskian 不从 Agent 的自然语言输出中自动提取并授权目录，避免绑定错误路径。

## 三、任务寻址与默认值

推荐的确定性语法：

```text
#cursor week-report 写一下本周周报
#codex D:\cursorwork\taskian 检查代码并运行测试
#task week-report 写一下本周周报
```

- `#cursor`、`#codex`：明确选择 Agent。
- `#task`：使用 `default_agent`。
- 第二个参数可以是已注册的项目名称或绝对目录。
- 任务正文可以和命令写在同一行，也可以从下一行开始。

设置当前项目后可以省略项目：

```text
#use week-report
#cursor 写一下本周周报
#task 写一下本周周报
```

解析优先级为：消息明确指定的目录或项目名称、当前会话项目、全局默认项目。缺少可确定的项目时必须询问用户，不能在未知目录启动 Agent。

普通文本仍优先作为唯一待回答任务的回答，避免把 Agent 问题的答案误创建为新任务。0.4.1 起，当没有等待回答的任务时，个人模式中的普通文本会作为默认 Agent 的新任务；没有选择项目时使用当前用户主目录作为“全局”工作目录。

## 四、微信 Help 命令

以下消息都应显示帮助，不区分大小写：

```text
help
#help
帮助
```

完整帮助至少列出：

- 创建任务：`#task`、`#codex`、`#cursor`。
- 回答问题：`#reply`。
- 查看和取消任务：`#status`、`#cancel`。
- 项目管理：`#project add/list/show/rename/remove/find`、`#use`。
- 当前默认 Agent、当前项目和可用 Agent。
- Windows 与 Linux 路径示例。

支持分组帮助以减少微信消息长度：

```text
help task
help project
help agent
help examples
```

控制命令优先于普通回答。如果用户确实要把单词 `help` 作为 Agent 问题的答案，应使用：

```text
#reply <任务号> help
```

帮助内容在程序内集中维护并由解析测试覆盖，避免解析器、README 和微信帮助长期不一致。长帮助按 iLink 消息长度自动分段。

## 五、首次启动与前后台选择

Taskian 的初始化必须在可见终端中完成，长期调度默认转交给当前系统用户的后台服务。Windows 使用任务计划程序，Linux 使用 systemd user service；二者由相同的 `taskian service` 命令管理。

### Windows 双击体验

用户在资源管理器中双击 `taskian-windows-amd64.exe` 时，应出现并保持一个 CMD/控制台窗口，而不是一闪而过。

### 首次运行

1. 打印 Taskian 欢迎信息和版本号。
2. 自动探测 Codex、Cursor 及其登录状态，并显示结果。
3. 在 `%USERPROFILE%\.taskian\config.json` 自动生成个人模式配置。
4. 如果尚未绑定 iLink，直接在控制台打印二维码，同时保存 PNG 备用图。
5. 用户微信扫码后显示绑定成功信息。
6. 询问 `是否让 Taskian 在后台自动启动？[Y/n]`，直接回车视为 `Y`。
7. 选择 `Y` 时，将稳定版本的程序安装到 `%LOCALAPPDATA%\Taskian\taskian.exe`，创建当前用户的 Windows 计划任务并立即启动后台实例。
8. 启动器必须确认后台实例已获得单实例锁并通过启动预检，才显示“后台运行成功，现在可以关闭窗口”。
9. 选择 `n` 时才由当前窗口进入前台 `serve`；此时关闭窗口会停止 Taskian。

个人模式允许项目注册表初始为空，因此自动生成配置不需要猜测或授权某个目录。

Windows 计划任务必须以完成 Agent 登录的同一个用户身份运行，使后台 Taskian 能读取同一用户的 Codex/Cursor 会话和 iLink 凭据。默认采用用户登录时自动启动的方式，不要求管理员权限，不使用 SYSTEM 身份。

### 后续运行

- 已安装且后台实例正在运行：显示状态、日志位置和管理命令，不启动第二个实例。
- 已安装但后台实例未运行：尝试启动计划任务并显示结果。
- 未安装后台任务且配置、登录有效：再次询问后台安装；选择 `n` 时前台运行。
- 配置存在但 iLink 登录失效：在原窗口重新显示二维码，扫码后恢复服务。
- 未找到任何 Agent：仍然完成 iLink 设置并启动，清楚提示安装方法，后续由 0.3 健康检查自动发现新安装的 Agent。
- 初始化或启动失败：打印可理解的原因和修复命令；从资源管理器启动时显示“按回车退出”，防止窗口立即关闭。

### Linux 首次启动与 systemd

Linux，特别是无图形界面的服务器，长期运行默认使用 systemd user service。推荐流程是：

1. 用户在 SSH/本地终端运行无参数 `taskian` 或 `taskian init`。
2. 在当前终端完成自动配置、Agent 探测和二维码扫码。
3. 询问 `是否让 Taskian 在后台自动启动？[Y/n]`，默认选择 `Y`。
4. 安装 `~/.config/systemd/user/taskian.service`，执行 daemon reload、enable 和 start。
5. 确认 user service 进入 active 状态后，提示用户可以退出 SSH。

服务必须以拥有 Codex/Cursor 登录状态的同一 Linux 用户运行。不得默认创建 root/system service。对于需要用户退出登录后仍持续运行的 Rocky Linux 等服务器，初始化器应检测 user linger 状态并给出明确命令：

```text
sudo loginctl enable-linger <当前用户名>
```

Taskian 不得自行请求或保存 sudo 密码；没有 linger 时要明确说明服务可能在用户会话结束后停止。

### 统一后台管理命令

```text
taskian service install
taskian service start
taskian service stop
taskian service restart
taskian service status
taskian service logs
taskian service uninstall
```

- Windows 后端使用任务计划程序，Linux 后端使用 systemd user service。
- `uninstall` 只删除后台启动注册，不删除配置、iLink 登录、SQLite、项目或 Agent 会话。
- `logs` 在 Linux 显示/跟随 user journal，在 Windows 读取 Taskian 用户日志文件。
- 后台标准日志应带大小限制和轮转，Windows 默认存放在 `%USERPROFILE%\.taskian\logs`；日志不得包含 iLink Token。
- 安装信息记录绝对程序路径、配置路径和版本，升级时可原子替换稳定安装目录中的程序。

### 单实例与前后台交接

- 同一个数据库/iLink 身份只允许一个 `serve` 实例，使用跨平台进程锁保护。
- Windows 初始化器选择 `Y` 后，先注册后台任务，再停止任何临时前台服务并启动后台实例，禁止两个实例同时长轮询 iLink。
- 后台启动成功必须通过进程锁、状态文件/心跳和启动预检三项确认；仅创建计划任务或 systemd unit 不算成功。
- 后台启动失败时保持当前窗口，显示诊断信息，并允许用户重试或退回前台运行。
- iLink 登录过期时后台服务写入明确状态和日志；用户在前台执行 `taskian ilink login` 后，`taskian service restart` 恢复运行。

### 命令行兼容

- 显式运行 `taskian serve` 时保持服务命令语义，错误应返回非零退出码，便于 systemd、脚本和服务管理器处理。
- 无参数运行 `taskian` 时进入面向人的启动器/初始化流程。
- Linux/macOS 无参数运行也可使用相同流程；Linux 默认建议安装后台服务，“按回车退出”仅用于检测到 Windows 交互控制台的场景。
- 提供 `taskian init` 以便用户主动重新进入初始化或修改全局默认设置，但不得静默覆盖已有配置。

## 六、建议的自动生成配置

```json
{
  "mode": "personal",
  "default_agent": "codex",
  "database_path": "~/.taskian/taskian.db",
  "channel": {
    "type": "ilink",
    "state_path": "~/.taskian/ilink.json"
  },
  "health": {
    "enabled": true,
    "interval": "5m"
  }
}
```

Agent 路径由探测结果在运行时解析，不要求把本机绝对路径固化进可移植配置。项目别名保存在 SQLite，不需要反复改写 JSON。

## 七、数据模型

SQLite 新增或扩展：

- `projects`：规范化名称、绝对路径、创建时间、更新时间和最近使用时间。
- `conversation_preferences`：通道、会话 ID、当前项目和可选的会话默认 Agent。
- 项目管理消息继续使用现有 inbound message ID 做幂等处理。

删除或重命名项目别名不能修改磁盘；正在运行和历史任务保存任务创建时的实际目录快照，不因别名后来变化而改变。

## 八、验收标准

- 全新 Windows 用户双击程序后，在同一个 CMD/控制台窗口完成配置生成、二维码扫码和服务启动。
- Windows 选择默认的 `Y` 后，计划任务立即启动且通过后台状态确认；关闭 CMD 后 Taskian 继续收发消息。
- Windows 选择 `n` 时保持前台运行，关闭 CMD 后 Taskian 正常停止；再次运行不会丢失配置或 iLink 登录。
- 双击启动发生错误时窗口不会一闪而过，也不会错误地报告后台启动成功。
- Linux amd64 能安装、启停和查询 systemd user service；扫码和后台启动在同一初始化流程中完成。
- Linux 对未启用 linger 的情况给出准确提示，不默认以 root 身份运行。
- `taskian service` 的 install/start/stop/restart/status/logs/uninstall 在对应平台有自动化测试或可隔离的集成测试。
- 前台与后台同时启动时单实例锁能阻止第二个实例接管相同 iLink 状态。
- 无项目配置的个人模式能够启动并接收 `help`。
- 微信发送 `help`、`#help` 或 `帮助` 均能看到任务与项目管理命令。
- 能通过项目名称或绝对路径调用 Codex/Cursor；未指定 Agent 时使用默认 Agent。
- `#project add/list/show/rename/remove/find` 与 `#use` 行为有自动化测试，重启后注册信息仍存在。
- `#project remove` 不删除磁盘文件；`find` 不调用模型且搜索范围有界。
- 唯一待回答任务与新任务命令不会混淆。
- 0.3 严格项目配置能够迁移或继续运行。
- Windows amd64、Linux amd64、macOS amd64/arm64 构建、测试和竞态检查通过。

## 九、暂不包含

- 图形化桌面界面和系统托盘。
- 从 Agent 输出中自动信任或注册目录。
- 无限制的全盘后台索引。
- 绕过 Agent 沙箱或操作系统文件权限。

## 十、发布验证记录

- Go 单元测试和静态检查通过，覆盖个人配置、项目注册/重命名/删除、会话当前项目、微信帮助变体、单行任务路由和后台命令编码。
- Windows amd64 实机完成计划任务安装、立即启动、后台单实例锁确认、后台 Agent 探测、第二实例拒绝、停止和卸载闭环。
- Windows 计划任务验证为当前用户运行、登录时启动、允许电池供电、`ExecutionTimeLimit=PT0S`（不设 72 小时上限）。
- Windows 后台环境 PATH 缺少 Codex 时，Taskian 能从 `%LOCALAPPDATA%\OpenAI\Codex\bin` 的已知安装结构自动发现 CLI。
- 临时计划任务、测试数据库、日志和稳定目录测试副本已在验证后清除，不影响用户现有 iLink 数据。
- Linux systemd user service 由跨平台构建和命令单元测试覆盖；正式发布构建继续由 GitHub Actions 在 Linux runner 验证。

## Release Note 摘要

Taskian 0.4 提供全局个人模式、自动首次配置、Windows 双击扫码及任务计划程序后台启动、Linux systemd user service、统一后台管理、项目名称与目录动态注册、默认 Agent/当前项目，以及微信 `help` 命令。用户无需预先维护项目白名单，可以直接使用绝对目录，或将常用目录注册成简短项目名称；首次扫码后可默认转入后台并安全关闭终端。

### 0.4.1 修正

- 没有等待回答任务时，个人模式的普通文本直接创建默认 Agent 任务，不再静默忽略。
- 新增关机/重启的内置安全操作，必须在 2 分钟内使用一次性 `#confirm` 确认码确认。
- 修正终端二维码黑白模块方向，改用专用终端二维码渲染库；PNG 提升到 768 像素和高纠错级别。
- Windows 首次登录时自动打开高清二维码图片，规避传统 CMD 字体渲染对扫码的影响。

### 0.4.2 修正

- Codex 在个人模式“全局”目录或其他非 Git 目录运行时自动使用 `--skip-git-repo-check`，避免启动即退出。
- “关一下机”识别为内置关机请求，进入二次确认流程，不再错误发送给 Agent。
- Windows CMD 和持久化日志记录收到消息、任务路由、Agent 启动、实时输出、等待回答、完成与详细失败原因。
- Agent 失败时将诊断输出写入任务记录并返回微信，不再只显示 `exit status 1`。
